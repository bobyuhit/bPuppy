# bPuppy 硬件连接

## 硬件版本差异 — V2.0 (当前在用) vs V3.0 (待打样)

> **当前代码对应 V2.0 硬件** (IMU SDA=GPIO3)。V3.0 板打样回来后, 需切换代码 (IMU SDA→GPIO14、启用电池检测) 见下表, 不要直接用 V3.0 板跑 V2.0 程序。

| 信号 | V2.0 (当前在用) | V3.0 (待打样) |
|------|----------------|---------------|
| IMU SDA (IIC_SDA) | **GPIO3** (pin12) | GPIO14 (pin19) |
| IMU SCL (IIC_SCL) | GPIO21 (pin24) | GPIO21 (pin24) |
| 电池分压输出 | GPIO14 (pin19, ADC2_CH3) | **GPIO3** (pin12, ADC1_CH2) |
| 电池检测 | ⚠ 停用 (ADC2 在 BLE/WiFi 下不可用) | ✅ 启用 (ADC1) |
| IMU 型号 | ZY MPU6050 / MPU9250 (管脚兼容) | 同左 |

**V3.0 的唯一改动**: GPIO3 ↔ GPIO14 对调 —— IMU SDA 与电池分压互换, 使电池检测走 ADC1, 在 BLE/WiFi 下可用 (V2.0 的 GPIO14=ADC2 在蓝牙下读数失败)。其余管脚 (舵机/串口/摄像头/上拉) 两版完全一致。

**切换步骤 (V3.0 板到位后)**:
1. `frozen/balance.py` `calib_mag.py` `set_heading.py` `mpy_modules/sensors.py`: IMU init 改 `init(0, 14, 21, 0x68)`
2. `drivers/adc_driver.c`: `BPUPPY_ADC_ENABLE` 改回 `1` (GPIO3=ADC1_CH2)
3. 重新编译烧录

### 2. IMU (MPU6050 / MPU9250, I2C0) — V2.0

| 信号 | GPIO | 说明 |
|------|------|------|
| SDA | **3** | V2.0 接线 (V3.0 改为 14) |
| SCL | 21 | 两版一致 |
| 地址 | 0x68 | MPU6050 与 MPU9250 默认地址相同 |

- 电平: 3.3V
- 上拉: GPIO21 (SCL) 需 4.7kΩ; GPIO3 (SDA) 板载 4.7kΩ
- 型号: ZY MPU6050 或 MPU9250 **管脚完全兼容** (QFN-24 同封装、模块排针定义一致), 板子不用区分。差异在软件: WHO_AM_I (6050=0x68, 9250=0x71) 与有无 AK8963 磁力计
- **软件双芯片自适应** (`imu_driver.c`): WHO_AM_I 自动识别 — 0x68/0x69=MPU6050, 0x71/0x73=MPU9250。
  - MPU6050: 6轴 (加速度+陀螺仪), 无磁力计 → `read_raw()` 磁力计恒 0, **yaw 有漂移**, 磁力计校准自动跳过
  - MPU9250: 9轴 (含 AK8963), 磁力计修正 yaw 无漂移
  - REPL 查询: `bpuppy_imu.get_chip()` → `"mpu6050"`/`"mpu9250"`, `bpuppy_imu.has_mag()` → True/False (sensors.py 封装为 `imu.chip()` / `imu.has_mag()`)
- AUX (XCL/XDA): 已空置, 两芯片均无需外接 (MPU9250 的 AUX 被内部磁力计占用)
- V3.0: SDA 改到 GPIO14 (IIC_SDA), 腾出 GPIO3 给电池检测

### 6. ADC 电压测量 — 电池检测 (V2.0: 停用 / V3.0: 启用)

| 版本 | GPIO | 外设 | 状态 |
|------|------|------|------|
| V2.0 (在用) | 14 | ADC2_CH3 | ⚠ **停用** (BLE/WiFi 下 ADC2 读数失败) |
| V3.0 (待打样) | 3 | ADC1_CH2 | ✅ 启用 |

**V2.0 状态**: 电池分压接 GPIO14=ADC2_CH3。ADC2 与 BLE/WiFi 射频硬件共享, 蓝牙一开读数即失败 (ESP_ERR_TIMEOUT); 且 GPIO3 被 IMU SDA 占用, 无可用 ADC1 脚 → **V2.0 上电池检测停用** (`adc_driver.c` `BPUPPY_ADC_ENABLE=0`)。

**V3.0 (打样后)**: IMU SDA 改到 GPIO14, GPIO3=ADC1_CH2 腾出接电池, ADC1 在 BLE/WiFi 下可用 → 启用。

**分压接线 (两版相同, R4=51k/R5=10k):**
```
电池正 ──[R1 51kΩ]──┬── GPIO3 (V3.0) / GPIO14 (V2.0)
                     │
GND  ────[R2 10kΩ]──┤
```
- 分压比 = 10/61 ≈ 0.164; 满电 8.4V → ADC ~1.38V; 标称 7.4V → ADC ~1.21V
- 软件换算: `电池电压 = bpuppy_adc.read_mv() × 6.1 / 1000` (V)

**注意:** ADC2 (GPIO11~20) 在 BLE/WiFi 下读数失败, 不可用——V3.0 特意把电池改到 ADC1 的 GPIO3。

## 排他性复用 (Exclusive Multiplexing)

以下 GPIO 与摄像头 DVP 总线共享引脚。**摄像头和外设不能同时使用**——两边均在 MicroPython 中手动初始化/释放，上电默认均为高阻输入，无竞争。

| GPIO | 复用功能 A | 复用功能 B | 切换方式 |
|------|-----------|-----------|---------|
| 4 | UART1 TX | CAM SCCB SDA | `u1_init` / `u1_stop` ↔ `camera.init` / `camera.deinit` |
| 5 | UART1 RX | CAM SCCB SCL | 同上 |
| 9 | I2C1 SDA | CAM D1 (Y3) | `i2c.init` / `i2c.deinit` ↔ `camera.init` / `camera.deinit` |
| 10 | I2C1 SCL | CAM D3 (Y5) | 同上 |

### 使用规则

```
使用 UART1/I2C1 前  →  摄像头未 init (或已 deinit)
使用摄像头前        →  UART1 已 stop + I2C1 已 deinit
```

### MicroPython 示例

```python
# ---- 模式 1: 用 UART1 + I2C1 (摄像头关闭) ----
bpuppy_uart.u1_init(4, 5, 115200)
bpuppy_i2c.init(port=1, sda=9, scl=10, freq=100000)
# ... 通信 ...
bpuppy_i2c.deinit()
bpuppy_uart.u1_stop()

# ---- 模式 2: 用摄像头 (UART1/I2C1 释放) ----
import camera
camera.init()
# ... 拍照 ...
camera.deinit()
```

> **上电默认状态**: 所有复用脚均为高阻输入，不驱动任何信号。不会因上电时序导致冲突。

## 外部设备连接

### CI-33T 语音模块

```
CI-33T                    ESP32-S3
───────                   ────────
VCC (5V)  ───────────→   外部供电
GND       ───────────→   GND
PB5 (TX)  ───────────→   GPIO 19 (UART2 RX)
PB6 (RX)  ←───────────   GPIO 20 (UART2 TX)
```

- 电平: 两边都是 3.3V IO，直连
- 波特率: 115200

### micro:bit

```
micro:bit (金手指)        ESP32-S3
─────────────────        ────────
3V        ←──── 3.3V LDO 输出 (外部供电，不直连 ESP32)
GND       ──── GND
TX        ───→ GPIO 19 (UART2 RX)
RX        ←─── GPIO 20 (UART2 TX)
```

- 电平: 两边都是 3.3V IO，直连
- micro:bit 金手指 3V 脚只能接 3.3V，不要接 5V

### 5V I2C 设备

```
ESP32 (3.3V)             5V 设备
───────────     ┌───    ───────
GPIO9  ──── SDA ─┤TXS   SDA ── 5V I2C 设备 A
GPIO10 ──── SCL ─┤0104  SCL ── 5V I2C 设备 B
                 └───
```

- 使用 **I2C1 (GPIO9/10)** 作外接总线 (摄像头未用时可用, 见上方 I2C1 节)。IMU 的 I2C0 (GPIO3/21) 被占用, 不要再接设备
- 需要双向电平转换 (TXS0104E / PCA9306)
- 3.3V 侧 + 5V 侧各配上拉电阻

### 电池电压测量 — ⚠ V2.0 停用 / V3.0 启用

**V2.0 (当前硬件)**: 电池分压接 **GPIO14=ADC2_CH3**, 蓝牙/WiFi 下读数失败, 且 GPIO3 被 IMU SDA 占用 → **软件停用** (`BPUPPY_ADC_ENABLE=0`), `bpuppy_adc.read_mv()` 恒返回 -1。

**V3.0 (打样后)**: IMU SDA 改到 GPIO14, 电池分压改接 **GPIO3=ADC1_CH2** → 启用。

**分压 (两版相同, R4=51k/R5=10k):**

| 元件 | 参数 | 接脚 |
|------|------|---------|
| R1 (上分压) | 51kΩ | 电池正极 ↔ GPIO3 (V3.0) / GPIO14 (V2.0) |
| R2 (下分压) | 10kΩ | GPIO3 (V3.0) / GPIO14 (V2.0) ↔ GND |

```
分压比     = 10/61 ≈ 0.164
满电 8.4V → ADC 约 1.38V
标称 7.4V → ADC 约 1.21V
软件公式   = bpuppy_adc.read_mv() × 6.1 / 1000  (V)
```

**注**: 分压阻值与原理图一致 (R4=51k/R5=10k)。若以后换 33k/10k, 需把公式改为 ×4.3。

## 供电架构

```
电池 7.4V (2S LiPo)
  │
  ├─→ 5V LDO ─┬─→ ESP32-S3 VIN (5V)
  │            ├─→ CI-33T VCC (5V)
  │            └─→ 舵机电源 (5-7.4V 直供)
  │
  └─→ 3.3V LDO ──→ micro:bit 金手指 3V (如需)
```

## 蓝牙（BLE，无线）

蓝牙不占用 GPIO（射频无线）。bPuppy 的 BLE 模式**编译互斥**（见 README「蓝牙编译互斥」）：

| 模式 | 广播名 | GATT 服务 | 用途 |
|------|--------|-----------|------|
| **KittenBlock** (`BPUPPY_BLE_KEBLOCK`) | `bPuppy_XXXX` | Nordic UART (`6E400001`) + 广播 `0x6E40` | KittenBlock 图形化编程（无线 REPL） |
| **Hiwonder** (`BPUPPY_BLE_HIWONDER`) | `mechdog_XX` | FFE0 (`FFE1`/`FFE2`) | Wonderbot App 遥控 |

- 同一固件只能启用一个蓝牙模式，**不要同时编译**
- 切换：改 `drivers/micropython.cmake` 的编译宏，重新编译烧录
- KittenBlock 模式连接走 MicroPython REPL（`os.dupterm()` 桥接），支持无线上传 `main.py`
- 蓝牙连接平台支持：安卓（Chrome）、iPad（**Bluefy** 浏览器，因 Safari/Chrome 被 Apple 限制）、PC 桌面版
