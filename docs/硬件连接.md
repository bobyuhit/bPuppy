# bPuppy 硬件连接

## 硬件版本 — V3.0 (当前在用)

> **当前硬件 = V3.0** (IMU SDA=GPIO14, 电池检测启用, 舵机接线见下方舵机表)。

V3.0 把 IMU SDA 与电池分压互换: IMU SDA→GPIO14 (IIC_SDA), 电池分压→GPIO3 (ADC1_CH2), 使电池检测走 ADC1 在 BLE/WiFi 下可用。

### 2. IMU (MPU6050 / MPU9250, I2C0)

| 信号 | GPIO | 说明 |
|------|------|------|
| SDA | **14** | IIC_SDA |
| SCL | 21 | IIC_SCL |
| 地址 | 0x68 | MPU6050 与 MPU9250 默认地址相同 |

- 电平: 3.3V
- 上拉: GPIO21 (SCL) 需 4.7kΩ; GPIO14 (SDA) 板载 4.7kΩ
- 型号: ZY MPU6050 或 MPU9250 **管脚完全兼容** (QFN-24 同封装、模块排针定义一致), 板子不用区分。差异在软件: WHO_AM_I (6050=0x68, 9250=0x71) 与有无 AK8963 磁力计
- **软件双芯片自适应** (`imu_driver.c`): WHO_AM_I 自动识别 — 0x68/0x69=MPU6050, 0x71/0x73=MPU9250。
  - MPU6050: 6轴 (加速度+陀螺仪), 无磁力计 → `read_raw()` 磁力计恒 0, **yaw 有漂移**, 磁力计校准自动跳过
  - MPU9250: 9轴 (含 AK8963), 磁力计修正 yaw 无漂移
  - REPL 查询: `bpuppy_imu.get_chip()` → `"mpu6050"`/`"mpu9250"`, `bpuppy_imu.has_mag()` → True/False (sensors.py 封装为 `imu.chip()` / `imu.has_mag()`)
- AUX (XCL/XDA): 已空置, 两芯片均无需外接 (MPU9250 的 AUX 被内部磁力计占用)
- 电池分压接 GPIO3 (ADC1_CH2), 见下方 ADC 节

### 4. 通信串口 (UART2)

| 信号 | GPIO |
|------|------|
| RX | 20 |
| TX | 19 |
| 波特率 | 9600 (CI-33T) / 115200 (micro:bit) |

- 电平: 3.3V
- 用途: CI-33T 语音模块 / micro:bit 通信
- ⚠ **2026-08-19 起 UART2 引脚反转: TX=GPIO19, RX=GPIO20**。原因: CI-33T 实际接线 PA2(UART1_TX)→GPIO20、PA3(UART1_RX)←GPIO19, 为交叉对接(发对收), ESP32 侧把 TX 配在 GPIO19、RX 配在 GPIO20。原默认 TX=GPIO20/RX=GPIO19 已废弃, 勿按旧文档接线。
- ⚠ **GPIO19/20 = USB_D-/USB_D+，固件已关闭 TinyUSB 释放** (2026-08-19 实测根因): ESP32-S3 这两个脚是原生 USB 引脚, MicroPython 组件默认启用 TinyUSB CDC (`mpy_startup.c` `usb_init()`), 会初始化 USB-OTG PHY 接管 GPIO19/20 → UART2 TX 发不出波形、`machine.Pin(19)` 驱动无效。已在 `components/mr9you__micropython-helper/mpy_startup.c` 注释掉 `usb_init()` 调用。代价: USB-CDC 虚拟串口不可用 (REPL/烧录走 UART0=COM14, 不受影响)。详见 [操作指南.md](操作指南.md) 2.1 语音控制。
- 上电由 `frozen/voice.py` 自动初始化 (9600)，micro:bit 需手动 `bpuppy_uart.init(2, 19, 20, 115200)`

### 6. ADC 电压测量 — 电池检测

电池分压接 **GPIO3 = ADC1_CH2** → **启用** (`adc_driver.c` `BPUPPY_ADC_ENABLE=1`)。ADC1 在 BLE/WiFi 下可用。

**分压接线 (R1=51k/R2=10k):**
```
电池正 ──[R1 51kΩ]──┬── GPIO3 (ADC1_CH2)
                     │
GND  ────[R2 10kΩ]──┤
```
- 分压比 = 10/61 ≈ 0.164; 满电 8.4V → ADC ~1.38V; 标称 7.4V → ADC ~1.21V
- 软件换算: `电池电压 = bpuppy_adc.read_mv() × 6.1 / 1000` (V)

**注意:** 电池必须接 ADC1 (GPIO3)。ADC2 (GPIO11~20) 在 BLE/WiFi 下读数失败, 不可用。

### 11. WS2812 电池电压指示灯 (GPIO48)

GPIO48 接一颗 WS2812 RGB LED, 用作电池电量指示。`bpuppy_adc.init()` 初始化 ADC 后**自动激活** (C 驱动 led_driver.c), 无需额外代码; 颜色随电池电压 (标定后) 变化:

| 状态 | 电压 | 颜色 |
|------|------|------|
| 满电 | ≥7.4V | 蓝色 |
| 渐变 | 6.6~7.4V | 蓝 → 紫 → 红 连续过渡 |
| 低压 | ≤6.6V | 红色 |
| 危险 | <6.4V | 红色闪烁 (~0.5s 周期) |

- 电压为最小二乘标定值 (同 mpy_modules/batt.py); 阈值可改 `drivers/led_driver.c` 顶部 `BATT_HIGH_V / BATT_LOW_V / BATT_BLINK_V`。
- 手动控制: `import bpuppy_led; bpuppy_led.set_color(r,g,b)` / `bpuppy_led.off()` / `bpuppy_led.batt(on=False)`。
- 驱动: ESP-IDF RMT (TX 通道 0), 与 MicroPython 的 `machine.bitstream` (默认通道 3) 互不冲突。

## 排他性复用 (Exclusive Multiplexing)

以下 GPIO 与摄像头 DVP 总线共享引脚。**摄像头和外设不能同时使用**——两边均在 MicroPython 中手动初始化/释放，上电默认均为高阻输入，无竞争。

| GPIO | 复用功能 A | 复用功能 B | 切换方式 |
|------|-----------|-----------|---------|
| 4 | UART1 TX | CAM SCCB SDA | `u1_init` / `u1_stop` ↔ `camera.init` / `camera.deinit` |
| 5 | UART1 RX | CAM SCCB SCL | 同上 |
| 9 | I2C1 SDA | CAM D1 (Y3) | `i2c.init` / `i2c.deinit` ↔ `camera.init` / `camera.deinit` |
| 10 | I2C1 SCL | CAM D3 (Y5) | 同上 |

### 使用规则

```
使用 UART1/I2C1 前  →  摄像头未 init (或已 deinit)
使用摄像头前        →  UART1 已 stop + I2C1 已 deinit
```

### MicroPython 示例

```python
# ---- 模式 1: 用 UART1 + I2C1 (摄像头关闭) ----
bpuppy_uart.u1_init(4, 5, 115200)
bpuppy_i2c.init(port=1, sda=9, scl=10, freq=100000)
# ... 通信 ...
bpuppy_i2c.deinit()
bpuppy_uart.u1_stop()

# ---- 模式 2: 用摄像头 (UART1/I2C1 释放) ----
import camera
camera.init()
# ... 拍照 ...
camera.deinit()
```

> **上电默认状态**: 所有复用脚均为高阻输入，不驱动任何信号。不会因上电时序导致冲突。

## 外部设备连接

### CI-33T 语音模块

```
CI-33T                    ESP32-S3
───────                   ────────
VCC (5V)  ───────────→   外部供电
GND       ───────────→   GND
PA2 (TX)  ───────────→   GPIO 20 (UART2 RX)   ← UART1_TX 对 UART2 RX
PA3 (RX)  ←───────────   GPIO 19 (UART2 TX)   ← UART1_RX 对 UART2 TX
```

- 电平: 两边都是 3.3V IO，直连
- 波特率: **9600**（上电由 `frozen/voice.py` 自动初始化，协议见 [操作指南.md](操作指南.md) 2.1 语音控制）
- 配置: 命令词输出数据区字节、串口输入匹配 `AA 55 <数据> 55 AA` 帧，均在智能公元平台完成
- ⚠ **PA2/PA3 = 模块 UART1**（UART1_TX/UART1_RX）。模块另有 **PB5/PB6 = UART0 烧录口**（PB5=TX、PB6=RX），**不要用作数据通信**。

### micro:bit

```
micro:bit (金手指)        ESP32-S3
─────────────────        ────────
3V        ←──── 3.3V LDO 输出 (外部供电，不直连 ESP32)
GND       ──── GND
TX        ───→ GPIO 20 (UART2 RX)
RX        ←─── GPIO 19 (UART2 TX)
```

- 电平: 两边都是 3.3V IO，直连
- micro:bit 金手指 3V 脚只能接 3.3V，不要接 5V

### 5V I2C 设备

```
ESP32 (3.3V)             5V 设备
───────────     ┌───    ───────
GPIO9  ──── SDA ─┤TXS   SDA ── 5V I2C 设备 A
GPIO10 ──── SCL ─┤0104  SCL ── 5V I2C 设备 B
                 └───
```

- 使用 **I2C1 (GPIO9/10)** 作外接总线 (摄像头未用时可用, 见上方 I2C1 节)。IMU 的 I2C0 (GPIO3/21) 被占用, 不要再接设备
- 需要双向电平转换 (TXS0104E / PCA9306)
- 3.3V 侧 + 5V 侧各配上拉电阻

### 电池电压测量

电池分压接 **GPIO3 = ADC1_CH2** → **启用**, `bpuppy_adc.read_mv()` 返回引脚电压 (×6.1 换算电池电压)。

**分压 (R1=51k/R2=10k):**

| 元件 | 参数 | 接脚 |
|------|------|---------|
| R1 (上分压) | 51kΩ | 电池正极 ↔ GPIO3 |
| R2 (下分压) | 10kΩ | GPIO3 ↔ GND |

```
分压比     = 10/61 ≈ 0.164
满电 8.4V → ADC 约 1.38V
标称 7.4V → ADC 约 1.21V
软件公式   = bpuppy_adc.read_mv() × 6.1 / 1000  (V)
```

**注**: 分压阻值与原理图一致 (R4=51k/R5=10k)。若以后换 33k/10k, 需把公式改为 ×4.3。

## 蓝牙（BLE，无线）

蓝牙不占用 GPIO（射频无线）。bPuppy 的 BLE 模式**编译互斥**（见 README「蓝牙编译互斥」）：

| 模式 | 广播名 | GATT 服务 | 用途 |
|------|--------|-----------|------|
| **KittenBlock** (`BPUPPY_BLE_KEBLOCK`) | `bPuppy_XXXX` | Nordic UART (`6E400001`) + 广播 `0x6E40` | KittenBlock 图形化编程（无线 REPL） |
| **Hiwonder** (`BPUPPY_BLE_HIWONDER`) | `mechdog_XX` | FFE0 (`FFE1`/`FFE2`) | Wonderbot App 遥控 |

- 同一固件只能启用一个蓝牙模式，**不要同时编译**
- 切换：改 `drivers/micropython.cmake` 的编译宏，重新编译烧录
- KittenBlock 模式连接走 MicroPython REPL（`os.dupterm()` 桥接），支持无线上传 `main.py`
- 蓝牙连接平台支持：安卓（Chrome）、iPad（**Bluefy** 浏览器，因 Safari/Chrome 被 Apple 限制）、PC 桌面版

**指令发送不全 — 根因与完整修复**（2026-08 实测确认）：

KittenBlock 指令偶尔/频繁**截断在 20 字节处**（如 `_speed = 2.5; _strid`）。排查结论是两层因素叠加，只修 MTU 不够：

1. **KittenBlock 的 JS 库自身按 20 字节硬编码分包**（Nordic UART 经典 `MAX_CHUNK_SIZE=20`），与链路 ATT MTU 无关。固件 MTU 交换到 256 后，KittenBlock 仍把一条长指令拆成多个 20 字节的独立 ATT 写。所以「长指令跨包」无法靠 MTU 消除，只能保证单包不跨。
2. **设备侧 echo 洪峰饿死后续包（真正的丢包点）**：MicroPython REPL 普通模式逐字符 echo，`ble_stream.c` 旧实现每 echo 一个字符就发一个 NOTIFY（每字符分配一块 NimBLE MSYS_1 mbuf，池仅 12 块）。chunk1 的 echo 洪峰瞬间吃光小包池 → chunk2 到达时无 mbuf 可分配 → 在 NimBLE host 层被丢弃；chunk3（`\n`）在池恢复后幸存 → 现象恰为「chunk1 + `\n` 到了，chunk2 丢了」。

**修复（`ble_stream.c` echo 批量打包）**：把逐字符通知改为**攒到一整行（遇 `\n`）或超时（30ms）再发一个 NOTIFY**（MTU 256 单包可装 253 字节）。一条命令的 echo 从几十个通知变 1 个，mbuf 分配从每字符 1 块 → 每行 1 块，echo 洪峰消失，后续分包不再被饿死。KittenBlock 是命令级流控（等 `>>>` 提示符再发下一条，提示符由 30ms 超时兜底发出），批量 echo 不影响时序。

配套改动：接收缓冲 512→4096、写满时丢新字节而非覆盖未读数据；连接成功后主动 `ble_gattc_exchange_mtu()`（MTU→256，单包不跨，消除 20 字节边界上的另一种丢包）。验证方法：串口日志确认 KittenBlock 每个 `len=20` 分包都到达 GATT 写回调，串口查询 `print(_stride)` 返回 `70`（修复前为 `NameError`）。
