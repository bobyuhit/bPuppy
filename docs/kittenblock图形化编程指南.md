## 一、KittenBlock 蓝牙编程（Nordic UART）★

bPuppy 支持 **KittenBlock 图形化编程**通过蓝牙连接（Nordic UART 服务 + dupterm REPL）。**固件蓝牙模式必须编译为 KittenBlock**（`BPUPPY_BLE_KEBLOCK`，见 [AGENTS.md](../AGENTS.md) 的「蓝牙编译互斥」）。

- 设备名：`bPuppy_XXXX`（XXXX = BT MAC 后 4 位，与 WiFi 热点同名）
- 广播服务：`0x6E40` + Nordic UART（`6E400001`）
- KittenBlock 连接后走 MicroPython REPL：在线执行积木、无线上传 main.py 都支持

**平台使用**：见 [二、导入 bPuppy 扩展](#二导入-bpuppy-扩展)（含 iPad Bluefy 方案）。

> 与 Hiwonder 模式**编译互斥**：同一固件只能启用一个蓝牙模式，KittenBlock 模式广播 `bPuppy_XXXX`，Hiwonder 模式广播 `mechdog_XX`。**当前固件就是 KittenBlock 模式**，而 Hiwonder 模式那套（2.3）已随 `ble_hiwonder.py` 一起移除，所以实际上只剩这一个模式可用。

## 二、导入 bPuppy 扩展

用 KittenBlock（Scratch 积木式编程软件）拖积木给 bPuppy 编程，上传后机器狗按程序自主运行。**无需写代码**，适合小朋友。

### 2.1 两种导入方式

**方式 1：URL 导入（推荐）**

1. 打开 KittenBlock
2. 扩展 → 用户扩展 → **URL 导入** → 粘贴：
   ```
   https://raw.githubusercontent.com/bobyuhit/bPuppy/master/bpuppy-kittenblock.zip
   ```
3. 自动下载并加载，硬件选择列表出现 **bPuppy 机器狗**，选中它

> URL 必须以 `.zip` 结尾，否则导入失败。此 URL 对应 bPuppy 项目的 GitHub 仓库，扩展更新后刷新重新导入即可。

**方式 2：本地 zip 导入**

1. 左下角扩展页面 → **导入外部插件** → 选择 `bpuppy-kittenblock.zip`（位于项目根目录）
2. 硬件选择列表出现 **bPuppy 机器狗**，选中它

> ⚠ 如果之前导入过旧版本，请先删除用户扩展目录里的旧 bPuppy（`C:\Users\<用户名>\AppData\Roaming\Kittenblock\local-ext\` 下的 `bpuppy-kittenblock` 文件夹），再重新导入。

**在线编程**：也可以访问 https://kblock.kittenbot.cc/ 在网页上在线编程（需连接硬件）。

### 2.2 iPad 使用（Bluefy 浏览器）★

**iPad Safari/Chrome 的 Web Bluetooth 被 Apple 限制**，无法直接蓝牙连接。用 **Bluefy**（iOS 专用的 Web Bluetooth 浏览器）绕过：

1. App Store 搜索 **Bluefy**（Web BLE Browser）安装
2. 打开 Bluefy → 访问 `https://kblock.kittenbot.cc/`
3. URL 导入 bPuppy 扩展：
   ```
   https://raw.githubusercontent.com/bobyuhit/bPuppy/master/bpuppy-kittenblock.zip
   ```
4. 选 bPuppy → 蓝牙连接 → 扫描 `bPuppy_XXXX` → 连接
5. 拖积木 / 上传程序

> ⚠ **平台支持汇总**：
> - **安卓**：Chrome 打开 kblock.kittenbot.cc 即可（Web Bluetooth 原生支持）
> - **iPad**：必须用 Bluefy（Safari/Chrome 不支持 Web Bluetooth）
> - **PC 桌面版**：KittenBlock 桌面版，串口或蓝牙（PC 需蓝牙适配器）
> - **iPad KittenBlock App**：不推荐（App 无法加载 URL 导入的自定义主板扩展）

## 三、积木编程

选中 bPuppy 后，左侧积木区会出现 bPuppy 积木：

```
🏁 当绿旗被点击（事件区拖出）
🟠 姿态动作: 站立 / 蹲下 / 坐下 / 邀玩 / 挥手 / 等待 [1] 秒
🟢 运动控制: 停止 / 前进 / 后退 / 左转 / 右转
🎙️ 语音功能: 当收到 [指令▼]（下拉选：停止/前进/后退/左转/右转/加速/减速/点头/站立/蹲下/坐下/摇手/邀玩/播报电压/声音角度） / (声音角度) / 狗叫 [汪汪/嘤嘤▼] / 播报数字 [0-100]
🟣 舵机控制: 舵机 [左前大腿▼] 设为 [90]° / 过渡速度 [3]°/帧 / 执行姿态 / 舵机 [左前大腿▼] 的角度 / 摆动 [舵机▼] ±[10]° [4]Hz [8]次   ← 往复摆动也归这里
🔵 高级运动控制: 运动参数 步长 [70] mm 身体高度 [70] mm 抬脚高度 [30] mm / (步长) (身体高度) (抬脚高度) / 速度 [2.5] 方向 [前进▼] / (速度) (方向) / 切换步态 [自适应▼] / 转弯率设为 [0] / (转弯率) / 身体姿态 俯仰 [0] 度 滚转 [0] 度 / <设置成功？>
🟡 传感器功能: 初始化 IMU / (横滚角) / (俯仰角) / (偏航角) / 航向锁定 偏转 [30] 度 / 解除航向锁定
⚙️ 系统高级设置: 重心偏移 [0] mm   ⚠ 会存进板子（掉电保留）
```

> **「高级运动控制」是「设置 → 读数」成对排的**，顺序为：
> 运动参数 → (步长)(身体高度)(抬脚高度) → 速度方向 → (速度)(方向) → 切换步态 →
> 转弯率设为 → (转弯率) → 身体姿态 → <设置成功？>，方便"设完就读"。
> `<设置成功？>` 反映**所有**设置类积木的结果，所以放在这一类最末。
> 读数积木可勾到舞台上实时显示。
>
> 几条常用约束：`运动参数` 一个块改**三个**身体尺寸；`速度 方向` 里选「后退」= 只改**方向**，
> 步长幅度不变；`身体姿态` 默认参数下 |俯仰|≤3.7° / |横滚|≤6.2°；`重心偏移` 默认参数下只到 ±11.4mm ——
> 超了整条被拒且不写（详见下面「参数被拒了怎么知道」）。
>
> 🆕 **「航向锁定 偏转 [ ] 度」= 从现在这个方向「再转 N 度」，然后锁住它** —— 收的是**相对量**，
> 不是"转到 N 度"。锁上之后狗自己纠着走直线，被推歪也会转回来；走着走着改主意，再点一次即可（**立即生效**）。
> 「解除航向锁定」只是**松开转向**，**不停狗** —— 要停狗用「运动控制 → 停止」。
> 首次点它要花 0.6 秒确认姿态，但 KittenBlock 生成的程序开头会自动初始化 IMU，所以基本无感。

**程序必须从「当绿旗被点击」开始**，积木首尾相接成一条链。例如：

```
当绿旗被点击 → 前进 → 等待 2 秒 → 停止 → 等待 1 秒 → 挥手
```

bPuppy 上电由**原厂自动初始化**（舵机 + 站姿待命），程序从站姿开始，无需手动初始化。

> 切换步态的下拉选项：自适应(go) / 猫步(walk) / 小跑(trot) / 停止(stop)。走起来用「自适应」，speed≤4 是猫步、≥6 是小跑。蹲下/坐下/站立是姿态积木（见下），不走步态菜单。
> 参数积木（速度/方向/转弯率/运动参数/机身姿态/重心偏移）会**立即生效**并更新变量，运动积木用最新值；
> 参数超限（髋/膝角、抬腿过度、足端够不着）会被**校验拒绝**并保持原值 —— 被拒时**狗会嘤嘤叫一声**，
> `<设置成功？>` 变成假（怎么看，见下面「参数被拒了怎么知道」）。

**「运动参数」一个块改三个身体尺寸**（步长 / 身体高度 / 抬脚高度）。三个值**一起校验**，改一个可能整组被拒
（日志会提示是哪一项）。它**不打断当前步态** —— 狗该怎么走还怎么走，不会因为改了步长就掉头；
它**也完全不碰方向** —— 步长在这里只表幅度，「后退」块设过的方向原样保持。
⚠ **但它对「前进/后退/左转/右转」四个块没有影响** —— 那四个块用的是 `go` 步态，而 `go` 的步长/站高/抬脚由速度自己算
（原因见 [micropython编程指南.md](micropython编程指南.md) 的「运动指令 bpuppy_motion」节里 **「运行时参数」表**的警告 ——
`go` 会**无视**你设的步长/站高/抬脚，那三个值由速度自己算）。想让「运动参数」真的起作用，先用「切换步态」选 walk 或 trot。

**「速度 [2.5] 方向 [前进▼]」**把速度和方向合成一个块：选「后退」= 把**方向**改成后退，
**步长的幅度一点不变**。只动速度和方向，高度 / 抬脚 / 转弯率 / 步态都不碰，狗在走的话是**边走边改**。
（原来的「步长设为」「高度设为」「抬腿高度」三个块已并入「运动参数」，不再单独提供。）

> **「方向」读数积木**：显示板上当前方向（`+1` = 前 / `-1` = 后）。
> 注意跟「步长」读数的区别 —— 「步长」读出来是**带符号**的（幅度 × 方向，负号表示后退），
> 「方向」只看前后。想知道"迈多大步"看「步长」，「朝哪边走」看「方向」。

**参数被拒了怎么知道？** 超限时狗**不会报错、积木也不变红**，只是**没生效**（保持上一次成功的值）。三招看：

1. **听**：「运动参数」「速度…方向」「转弯率设为」「机身姿态」「重心偏移」被拒时**嘤嘤叫一声**（和「狗叫 [嘤嘤]」同一条声音；没装语音模块就听不到）。
2. **判断**：拖 `<设置成功？>` 积木（真/假）—— `如果 <设置成功？> 不成立` 里接你自己的提示。
   ⚠ 它只反映**最近一次**设置类积木的结果，所以要紧跟在被怀疑的那块后面。
3. **看**：把读数积木（(步长) (方向) (身体高度) (抬脚高度) (速度) (转弯率)）**左边的小方框勾上**，
   舞台上会出现数字框实时显示**板上生效值** —— 被拒时数字**停在上一次成功的值**不动。
   也可以看右侧代码面板的串口区（那是直接连着板子的终端）。

> ⚠ 两个已知限制：① 舞台上的数字框是**每帧**从板子读一次，**刷新比实际慢**，也会占串口；
> ② 主控板模式下积木区**没有「外观」分类**，拖不出「说」积木 —— 舞台显示只能靠第 3 条的读数框。
>
> ⚠ 「重心偏移」和「机身姿态」**没有读回接口**（`get_geometry()` 只给腿长和髋距），上面三招里
> 第 3 招（看读数）**对它们无效** —— 只能靠听声音、或 `<设置成功？>`。

> 「身体姿态」调俯仰 / 滚转（度），**设了就保持、不自动复位**。够不着时整条被拒（俯仰横滚都不写）。
> 「重心偏移」**会写进板子**（掉电保留，每拖一次写一次 flash；**被拒时不写**）—— 调好站稳后就不用再动它了。

### 3.1 语音控制（CI-33T 模块）🎙️

**语音组积木**：1 个事件积木（当收到 [指令▼]，下拉选择指令）+ 1 个变量积木（(声音角度)）+ 1 个发声积木（狗叫 [汪汪/嘤嘤▼]）+ 1 个播报数字积木（播报数字 [0-100]，发 `AA 55 72 <数字> 55 AA`）。

**事件积木用法**：拖出「当收到 [指令▼]」帽子积木，下拉选一条指令（如前进），下面接你的动作积木。每个指令各拖一个，可同时处理多条：

```
当收到 [前进▼] → 前进 → 等待 2 秒 → 停止
当收到 [停止▼] → 狗叫 [汪汪▼]
当收到 [邀玩▼] → 邀玩
```

**原理（2026-08-19；2026-09-16 修正位置）**：事件积木在生成代码**开头（正文之前）**生成 `def voiceWhen<所选指令>():` 函数（如选「前进」→ `def voiceWhenFwd()`），voice.py 后台线程按函数名自动注册为事件回调。收到语音指令时**只触发对应函数，不自动执行内置动作**——要不要动、怎么动，全由你的积木决定。

> ⚠ 固件**不做任何内置动作**（2026-08-19 起已移除），收到语音指令只触发事件积木，动作必须用积木自己编程。
>
> 📘 给接手者：语音「事件」系统的全链路原理、注册机制、改法与踩坑清单见 [AGENTS.md 语音「事件」系统节](../AGENTS.md)。

**发声积木**：一个积木「狗叫 [汪汪/嘤嘤▼]」，下拉选哪个就发哪个（2026-09-27 由「语音播放汪汪」/「语音播放嘤嘤」两个积木合并）：

| 下拉 | 生成代码 | 发出去的帧 |
|---|---|---|
| 汪汪 | `voice.say(*voice.SND_WANG)` | `AA 55 70 01 55 AA` |
| 嘤嘤 | `voice.say(*voice.SND_YING)` | `AA 55 70 02 55 AA` |

⭐ **狗叫类第一字节统一 `0x70`，靠第 4 个数字区分声音**（实测确认；嘤嘤 2026-09-27 从 `AA 55 71 02` 改来）。
以后加新声音、或想换某个声音的编号：改 `frozen/voice.py` 的 `SND_*` 常量 + 扩展下拉加一行，积木代码不用动。

> ⚠ 积木的 `pycode` **必须纯 ASCII**（2026-09-26 实测）：KittenBlock 生成/下发代码时会把非 ASCII
> 字符抹掉，原先写的 `voice.play('汪汪')` 到板上变成 `voice.play('')`，点哪个声音都汪汪。
> 所以改用 `voice.say(*voice.SND_xxx)` —— 纯 ASCII，且码值的唯一真源仍在固件常量里。
> （`voice.play('汪汪')` 本身没删，REPL / 自己写脚本仍可用。）

**声源角度（2026-09-26 新增）** 🎯 —— CI-33T 除了认词，还能靠 DOA 算法算出**声音从哪个方向来**，
做成**事件 + 变量**两件套：

- **事件**：下拉里的「声音角度」——`当收到 [声音角度] 指令`。一有角度上报就触发你的积木。
- **变量/reporter 积木**：`(声音角度)`，读出 `voice.SoundAngle` = 最近一次的角度（度，**0–180**）。

```
当收到 [声音角度▼] → 若 (声音角度) < 90 → 左转
```

> - **`0` 是有效方向**，所以初值用 `-1` 表示"开机后还没收到过"——判断时别把 `-1` 当成角度。
> - **声源持续存在时模块会连发角度帧，事件会连续触发**（实测日志里 `78000000` 连出 3 次）。
>   要"一有声音就响应"用事件；要"持续跟随声源"就轮询 `(声音角度)` 变量。
> - **本版只把角度原样解析出来，不定义 0°/180° 各是哪个方向** —— 方向含义待实测确定。
> - ⚠ 必须**下载到板子 + 复位**才生效（在线模式语音事件不生效，见 §3.2）。

### 3.2 ⚠ 在线跑 vs 下载到板子（先看这条）🎮

KittenBlock 有两种运行方式，**能干什么不一样**：

| 积木类型 | 点绿旗「在线」 | 点「上传/下载」+ RESET |
|---|---|---|
| 动作类（前进 / 停止 / 挥手 / 等待 …） | ✅ 能 | ✅ 能 |
| 🎙️ 语音事件（当收到 [指令▼]） | ❌ 不生效 | ✅ 能 |
| ⌨️ 键盘类（「按下x键?」「当按下x键」） | ✅ 能 | ❌ **完全失效** |

**键盘类积木只能在线玩。** 按键是在**电脑浏览器**里检测的 —— 板子上没有键盘，也没有这个功能。一旦「下载」到板子，这些积木会被翻译成恒假的 `if False:`，按什么键都不会有反应。

**另外：下载的程序里不要用「重复执行」。** 它会被翻译成顶格的 `while True:`，把这个程序**永久占在板子里空转**。加固前会让板子失联（KittenBlock 连不上、点什么都没反应，只能用串口删 `/main.py` 才救得回来）；2026-09-16 固件已加固不再失联，但仍然不建议这么写。

**做语音控制不需要「重复执行」** —— 语音事件本来就是回调式的：

```
当绿旗被点击 → 站立          ← 只做初始化
当收到 [前进▼] → 前进        ← 这几条是"来一句动一下"，不需要循环
当收到 [停止▼] → 停止
```

**想键盘 + 语音一起用**：把两段程序放在**两个不同的工程**里 —— 语音那个点「下载」（然后按 RESET），键盘那个只点绿旗在线跑。

> ⚠ **千万别把两段放在同一个工程里**：下载是**整个工程一起下**的，会把键盘那段里的 `while True:` 也一并下到板子上。

## 四、查看生成代码

右侧代码面板可实时查看积木翻译成的 MicroPython 代码。代码开头是自动注入的初始化，后面是积木对应的动作。

## 五、上传到 bPuppy

1. USB 线连接 bPuppy（设备管理器确认端口）
2. 点 KittenBlock 的**连接**（选串口）→ **上传**
3. **按一下 bPuppy 上的 RESET 键（或拔插 USB）**，让新程序生效

> ⚠ 点「上传」之前先确认程序里**没有键盘类积木**、也**没有「重复执行」** —— 理由见 [3.2](#32--在线跑-vs-下载到板子先看这条)。
>
> 🆘 万一板子失联了（KittenBlock 连不上、点什么都没反应）：把 USB 连上，用串口工具发一次 `Ctrl-C`，进 REPL 后执行 `import os; os.remove('/main.py')`，再按 RESET。**重烧固件没用**，`/main.py` 不在固件分区里。

机器狗会重启并按你的积木程序运行。
