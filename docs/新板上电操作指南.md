# bPuppy 新板上电操作指南

一块**全新的板子**从零到能用：烧固件 → 传文件 → 标定 → 验收。
照着从上往下做，每步末尾有**怎么算通过**。全程只要 **bTool** + 一个串口终端。

> 深度说明：命令与接口见 [micropython编程指南.md](micropython编程指南.md)，积木见 [kittenblock图形化编程指南.md](kittenblock图形化编程指南.md)，原理与源码见 [AGENTS.md](../AGENTS.md)。

---

## 🔴 先记住这条红线

**不要勾 bTool 的「先擦除整片 Flash」，不要用 `erase-flash`。**

板子的 NVS 里存着**舵机三点标定 / 几何 / 重心 / IMU 零偏 / 磁力计 / 电池系数**。
擦一次全没，只能从头重标（舵机 24 个点，靠手一只一只试）。

| 情况 | 做法 |
|---|---|
| 更新程序、升级固件 | **不勾**擦除，直接烧 |
| 改过分区表、板子状态不明烧不进去 | 才勾，勾之前想清楚标定会没 |
| 全新板第一次烧 | 不需要勾（空片没什么可擦） |

同时：**别把「升级 ESP-IDF」和「改分区表」放在同一次操作里**。

## 0. 准备

- [ ] **USB 数据线**（能传数据的；有些线只供电，插上毫无反应 —— 换根线往往比折腾驱动快）
- [ ] **串口驱动**：CH343 / CH340 或 CP210x。设备管理器里能看到 `USB-Enhanced-SERIAL CH343` 就对了
- [ ] **bTool.exe**：⬇ **https://github.com/bobyuhit/bTool/releases/latest/download/bTool.exe**（33.8 MB。`latest` 永远指向最新版，不用管版本号；历史版本在 [Releases](https://github.com/bobyuhit/bTool/releases) 页）
- [ ] **关掉别的串口程序**：ViperIDE / 串口助手 / 另一个 bTool（串口同一时间只能被一个程序占）
- [ ] **固件文件**：`build/micropython_bpuppy.bin`（+ 首次要的 bootloader / 分区表两件，见 §3）
- [ ] 可选：**万用表**（电池标定要用；不做就跳过 §5.2）
- [ ] 狗要**上电**（IMU 的电来自狗的主电源，**不来自 USB** —— 不上电时 IMU 一定读不到）

> **bTool 是什么？** 一个**免安装的 Windows 小程序**（33.8 MB），负责三件事：
> **烧固件、传文件、连 REPL 终端**。整个新板上电流程用它一个就够，不用装 Python 或别的工具链。
> 首次运行 Windows SmartScreen 可能拦一下（exe 未签名）：点「**更多信息 → 仍要运行**」。
> ⚠ **串口驱动它带不了**，要自己装（就是上面准备清单里那条 CH343 / CH340）。

> **固件从哪来？** 编译产物在 `build/`。自己编要在**宿主机 Git Bash** 里跑 `bash build.sh`（需要 Docker），
> **不要在容器里手动编译**。只改了 Python / 驱动 C 文件的日常升级，`build/micropython_bpuppy.bin` 一个文件就够。
>
> ⚠ **版本铁律**：MicroPython v1.22.1 **只能**配 ESP-IDF v5.1.2（**不是** v5.3 / v5.5）。完整编译环境见
> [AGENTS.md](../AGENTS.md) 的「编译环境」。
>
> ⚠ `build/bpuppy_merged.bin` 别用（没文档、且可能比最新固件旧）；仓库根的 `micropython_esp32.bin`
> **不是 bPuppy 固件**，别拿它烧。

## 1. 连上板子

1. 插上 USB，打开 bTool
2. 顶部 `串口:` 下拉 → 选板子的 COM 口（没有就点 `刷新`；还是空 → 见 §7）
3. `REPL 波特率:` 保持 **115200**
4. 点 `连接` → 右侧指示灯变绿：`● 已连接 COMx @115200`

**没看到 `>>>` 怎么办**：切到 `REPL 终端` 页，按 **`Ctrl+C`** 打断板子上正在跑的程序（开机自动跑的步态会挡住提示符）。

✅ **通过**：终端里敲 `Ctrl+D` 能看到 `MicroPython v...` 横幅。

## 2. 先判断：这块板要不要烧固件

| 板子状态 | 怎么做 |
|---|---|
| **全新板 / 不知道里面是什么** | 按**首次**处理 → §3 三个文件**全烧** |
| 已经在跑 bPuppy，只是升级程序 | **只烧 app** → §3 只加 `micropython_bpuppy.bin` |

判据是启动横幅：

```
bPuppy Robot Dog - ESP32-S3 MicroPython
Build: ...
WROOM-1 N16R8 | uPy v1.22.1 | IDF v5.1.2
```

看到这一屏 = 里面已经是 bPuppy 固件。没有 = 按全新板处理。

> ⚠ 改了固件后**必须物理 RESET**（或重上电）才生效 —— 在终端按 `Ctrl+D` 软复位**不会**重跑固件。

## 3. 烧固件（bTool「烧写」页）

**地址会自动按文件名填好**，不用你算：

| 加进来的文件 | 自动填的地址 | 什么时候要 |
|---|---|---|
| `build/bootloader/bootloader.bin` | `0x0` | 只有首次 / 改过 bootloader |
| `build/partition_table/partition-table.bin` | `0x8000` | 只有首次 / 改过分区表 |
| `build/micropython_bpuppy.bin` | `0x10000` | **每次都要** |

步骤：

1. 切到 `烧写` 页，点 `添加固件…`
2. 选文件 —— **首次选 3 个**（可多选）；**日常升级只选 `micropython_bpuppy.bin`**
3. 核对列表里的地址是 `0x0` / `0x8000` / `0x10000`（不对就**双击**地址那一格手改）
4. `烧写波特率:` 保持 **921600**（慢也可以选 115200，更稳）
5. **确认「先擦除整片 Flash」没勾**（默认就是不勾）
6. 点 `擦除并烧写`

> 按钮叫「擦除并烧写」是名字沿用 —— **没勾擦除时它就是「开始烧写」**。

✅ **通过**：日志最后是

```
✓ 烧写完成
[串口已重新打开]
```

烧完 bTool **自动硬复位板子**，然后应该看到启动横幅 + 狗自动站起来。

> 烧写时 REPL 会短暂断开（日志里 `[已释放串口供烧写使用]` → 烧完 `[串口已重新打开]`），**正常现象**。
>
> 只有**改过分区表**才需要额外做一步：擦掉 vfs 的首扇区让板子重新格式化（`erase-region 0x800000 0x1000`），
> 复位后看到 `VFS 是未格式化的新分区, 正在格式化...` 就对了。**首次烧全新片不需要这步。**

## 4. 传文件（bTool「文件管理」页）

板子上跑的程序分两种：**冻在固件里的**（烧固件才更新，上传无效）和**VFS 上的文件**（上传即生效）。
新板要传的**只有下面 3 个**：

| 文件 | 作用 | 不传会怎样 |
|---|---|---|
| `mpy_modules/pwm_ext_on.py` | 开机启用扩展舵机（宏 `EXT1/EXT2/EXT3`，默认只开 `EXT2`） | 扩展舵机读写报「未启用」 |
| `mpy_modules/camera_on.py` | 开机自动开网页图传 | 图传要手动开 |
| `mpy_modules/batt.py` | 电池标定工具（§5.2 要用） | 电池标定做不了，其余无影响 |

步骤：

1. 切到 `文件管理` 页，左侧选到本仓库的 `mpy_modules/` 目录
2. 右侧「设备 VFS」路径框保持 **`/`**（根目录）
3. 左边选中文件（可多选），点 **`上传 →`**
4. 传完在 `REPL 终端` 按 **`Ctrl+D`** 软复位让开关文件生效（**bTool 不会自动复位**）

三条限制，记一下：

- **文件夹会被跳过** —— 只能一个文件一个文件传，没有递归上传
- **同名文件会被静默覆盖** —— 没有提示，想保留就先 `← 下载` 备份
- **传纯 ASCII 的内容最保险** —— 中文可能丢字节、文件悄悄损坏。传完**核对一下文件大小**

✅ **通过**：复位日志里出现 `[pwm_ext_on] PWM_EXT2 ready` 之类的开关文件输出。

> `frozen/` 下的 11 个文件（`main.py` `poses.py` `calib_mag.py` `balance.py`
> `pwm_ext.py` `voltage.py` `voice.py` `camera_serial.py` `camera_stream.py`
> `heading_anchor.py` `heading_follow.py`）
> 都在冻结清单里，**上传上去也没用**，只能重编译 + 烧固件。
>
> ⚠ 反过来说：**同名文件别往板子上传** —— 板子根目录的文件**优先于**固件里的同名模块，
> 传一份旧的上去就会"固件明明升级了、行为还是老的"。
>
> ⚠ 要板子**开机自动跑**的，文件名只能是 `/main.py` —— 固件只执行它（开关文件是 `/camera_on.py`、`/pwm_ext_on.py`）。
> 传别的名字不会报错，但也**永远不会被执行**。

## 5. 标定

顺序：**舵机 → 电池 → IMU → 磁力计**。全部在 `REPL 终端` 里敲，**每一条都是当场生效、当场存 NVS**。

### 5.1 舵机三点标定 —— 必做（8 路 × 3 点）

先认通道号：

| 常量 | 值 | | 常量 | 值 |
|---|---|---|---|---|
| `LF_HIP` 左前大腿 | 0 | | `RF_HIP` 右前大腿 | 4 |
| `LF_KNEE` 左前小腿 | 1 | | `RF_KNEE` 右前小腿 | 5 |
| `LH_HIP` 左后大腿 | 2 | | `RH_HIP` 右后大腿 | 6 |
| `LH_KNEE` 左后小腿 | 3 | | `RH_KNEE` 右后小腿 | 7 |

```python
import bpuppy_motion, bpuppy_servo

bpuppy_motion.set_gait("stop")                        # 先停步态, 否则标定会被打断

bpuppy_servo.cal_point(bpuppy_servo.LF_HIP, 0,   3)   # 0°   点: 试 3
bpuppy_servo.cal_point(bpuppy_servo.LF_HIP, 1,  95)   # 90°  点: 试 95  (腿垂直)
bpuppy_servo.cal_point(bpuppy_servo.LF_HIP, 2, 178)   # 180° 点: 试 178
# ... 其余 7 路各标同样的 3 点 ...

bpuppy_motion.set_gait("go")                          # 恢复运动
```

**操作纪律**（这几条不守就白干）：

- 人的动作 = **眼睛看腿在不在理想位，不对就换个数重发同一行**。没有向导脚本，就是试数。
- **只能用 `cal_point`，不能用 `set_angle`** —— `set_angle` 发的是校准表插值后的值，边试边变，输出和输入对不上。
- 每次调用**立即写 NVS 并当场按你给的角度转过去**，**最后试对的那个值就是最终值**，没有单独的「保存」步骤。
- 扩展舵机（编号 8/9/10）**没有标定流程**，不用管。

> **为什么不能拿 `set_angle` 试？** 两者发出去的东西不一样：

| 调用 | 实际发出去的角度 | 用途 |
|---|---|---|
| `cal_point(ch, p, A)` | **原始 A** —— 跳过校准表 | 标定：试 + 存，一步完成 |
| `set_angle(ch, A)` | A 经三点插值后的值 | 平时用：传理论角度，自动校到位 |

标定途中校准表正在被改，`set_angle` 的输出跟着漂：0° 点已标成 3 之后，
`set_angle(ch, 95)` 实际发的是 `3 + (90−3)×95/90 = 94.8` —— **你输入的数和腿实际到的位置对不上**，
三点标完误差还会累加。

> **三点校准的原理**：每通道存 0°/90°/180° 三个点，中间角度**分段线性插值** ——
> 同时补偿**零点偏移**和**斜率 / 非线性误差**，NVS 掉电保留（开机自动 `load_cal`）。
> 角度方向约定（髋 0/90/180 指向、膝左右镜像）见 [AGENTS.md](../AGENTS.md) 的「舵机角度标定」表。
> 旧的 `cal(ch, ref)` 单点法只标 90° 点、不补偿线性误差，**已不推荐**（接口保留兼容）。

✅ **通过**：

```python
bpuppy_servo.set_angle(bpuppy_servo.LF_HIP, 90)   # 走的校准表, 应精确到位
bpuppy_servo.get_cal_point(bpuppy_servo.LF_HIP, 0) # 读回三点值
bpuppy_motion.show_geometry()                      # 只显示 90° 点
```

重启后仍然生效 = NVS 真写进去了。

> 不标的后果：`set_angle(90)` 原样发 90，舵机个体中位差 + 装配差全保留 → 站姿/蹲姿整体歪、腿可能不在理想位。

### 5.2 电池标定 —— 换板子才需要，**换电池不用**

标的是 **ADC 量程 + 分压电阻**的偏差，那是**板子**的属性，跟电池无关。需要万用表。

```python
import batt
batt.init()
batt.clear_cal_points()       # ★ 新板必须先清空 —— 出厂那 4 个点是别的板子的, 混进去会拟合错
batt.raw_v()                  # 看未标定显示值, 和万用表读数对照
batt.add_cal_point(6.17)      # 参数 = 万用表读到的电压; 换几个电压各来一次 (3~4 点)
batt.add_cal_point(7.00)
batt.add_cal_point(7.90)
batt.verify()                 # 自查残差, 目标 ≤0.05V
batt.apply_to_board()         # ★ 写进板子 NVS, 立即生效
```

✅ **通过**：`verify()` 残差 ≤0.05V；`bpuppy_led.batt_v()` 读数和万用表一致。

> 不标的后果：显示值系统性偏低 **0.67~0.79V** → 蓝色（满电）几乎不出现，电池还有 ~7.1V 就误报「危险」红色闪烁。
> 后悔了可以 `bpuppy_led.reset_cal()` 恢复出厂系数。

### 5.3 IMU 零偏标定 —— 必做

```python
import bpuppy_imu
bpuppy_imu.init(0, 14, 21, 0x68)      # 幂等, 已初始化会直接返回
bpuppy_imu.calibrate(300)            # ⚠ 机身放平、别动, 采 300 样本 (~3 秒)
```

**机身绝对水平放置**，别碰它 —— 不水平会把重力投影混进均值，引入错误。

✅ **通过**：打印出 `Gyro cal done`；把狗放平读 roll/pitch 应接近 0。

> 不标的后果：水平放置时姿态角**偏 ~12°**，直接毁掉自平衡（balance）和航向锁定（heading_anchor）。

### 5.4 磁力计椭球标定 —— 只有带磁力计才做

**不用自己判断有没有**，`start()` 会自己问出来并告诉你：

```python
import calib_mag
calib_mag.start()
```

拿起狗，按屏幕提示分三阶段旋转（左右倾斜 → 前后倾斜 → 水平转满 360°），
每轴覆盖达标后自动进入下一阶段，采够样本后自动拟合并存 NVS。

✅ **通过**：`✓ 校准完成! 残差: 0.0xxx`

- 残差 **<0.05** 好
- **>0.08** 会警告质量差 → 重新标一次
- 提示「没有磁力计 → 校准跳过」= 正常，6 轴模块（6050 / 真 6500）本来就不用标，yaw 会缓慢漂移，修不了

### 5.5 几何参数 / 重心 —— **换硬件后才需要**（新板不用）

腿长、髋距、关节限位、重心这几个和舵机标定一样**存在 NVS、掉电保留** ——
**新板出厂已经是正确值**，不用动。只有**改了结构**（换腿、改髋距）才要重设：

```python
import bpuppy_motion

bpuppy_motion.cal_ik(40, 45)                     # 腿长 (L1, L2 mm)
bpuppy_motion.set_body_dims(62.5, 59)            # 髋距 (前后半距, 左右半宽 mm) ⚠ 传的是**半距**
bpuppy_motion.set_joint_limits(0, 180, 10, 170)  # 限位 (髋 min/max, 膝 min/max 度)

bpuppy_motion.set_center(0)                      # 重心偏移 (正 = 脚前移/重心后移), 走起来后再微调

bpuppy_motion.show_geometry()                    # 打印全部 (人看)
bpuppy_motion.get_geometry()                     # 返回元组 (程序读)
```

⚠ 四个 setter 都会**校验并拒绝**非法值（被拒时保持原值），返回 `True`/`False`。

- [ ] 语音：开机日志有 `voice: CI-33T ready`，说「前进」→ 日志 `VOICE RX: bb3100ee` + `VOICE CMD: 0x31`
      （⚠ 平台侧命令词须已改成 `BB <CMD> 00 EE`，否则新固件认不出旧的裸 2 字节命令）
      ⚠ 固件**只转发事件、不做动作** —— 日志出现 `VOICE CMD: 0x31` 就算这条通过，**狗不会自己走**。
      想让狗真动，得在 KittenBlock 里拖「当收到 [前进] 指令」事件积木写程序；空板（没有 `/main.py`）到此为止。
      （**唯一例外**：`0x3F` 播报电压有固件内置动作 —— 说「播报电压」会自动报电量百分比，
       不需要用户程序。要出声得平台侧先配好 `AA 55 72 <数据> 55 AA` 的 0–100 词条。）
- [ ] 语音角度：拍手 → 日志 `VOICE RX: <角度>000000`，REPL 查 `voice.SoundAngle` 得到 0–180（初值 `-1`）
- [ ] 语音播报电量：说「播报电压」→ CI-33T 出声报出百分比（同时回归：说「点头」等**仍不出声**）

## 7. 踩坑速查

| 现象 | 原因 / 对策 |
|---|---|
| `串口:` 下拉是空的 | 换根**能传数据**的 USB 线 / 装驱动 / 板子没供电 |
| 连上了但看不到 `>>>` | 板子在跑程序 → `REPL 终端` 页按 **`Ctrl+C`** |
| 连上了、打字一点反应没有 | 看右上角按钮是不是 `切回 REPL`，是就点一下 |
| REPL 全是乱码 | REPL 波特率和固件不一致 → 改成 **115200** 并**重新连接** |
| 打开串口「拒绝访问」 | 被别的程序占着 → 关掉 ViperIDE / 串口助手 / 另一个 bTool |
| 烧写报 `Serial data stream stopped` | **别降波特率**。看日志里 `已加载 stub flasher` 是不是排在 `已提速到 921600 波特率` **前面** |
| 文件管理页按钮全是灰的 | 板上不是 MicroPython（顶部红字会说明） |
| 进 raw REPL 失败 | 板上有外设往串口吐数据干扰握手 → bTool 会自动重试 5 次，还不行多点几次 |
| 上传的文件不执行 | 固件只跑 `/main.py`；开关文件**必须叫** `camera_on.py` / `pwm_ext_on.py` |
| IMU 报 `[imu] NOT FOUND` | ①狗没上电（**IMU 电来自主电源，不来自 USB**）②接线松 ③真没接 |
| 电压恒 `-1.0`、电池灯不亮 | 启用了 `PWM_EXT1`(GPIO3) 或 `EXT3`(GPIO48) 抢了同脚 → **预期行为**，不是故障 |
| 标定完重启就没了 | 上一次操作勾了「先擦除整片 Flash」，或动过分区表的 `nvs` 两行 |

## 附：命令行版（可选，给习惯 CLI 的人）

```bash
# 全烧（首次 / 改过 bootloader 或分区表）
python -m esptool --chip esp32s3 --port COM6 --baud 921600 write-flash \
    0x0 build/bootloader/bootloader.bin \
    0x8000 build/partition_table/partition-table.bin \
    0x10000 build/micropython_bpuppy.bin

# 只烧 app（日常升级）
python -m esptool --chip esp32s3 --port COM6 --baud 921600 write-flash \
    0x10000 build/micropython_bpuppy.bin

# 硬复位（只读芯片 ID，不写不擦）
python -m esptool --chip esp32s3 --port COM6 --before default_reset --after hard_reset flash_id

# 传文件
python -m mpremote connect COM6 fs cp mpy_modules/batt.py :batt.py
```

硬复位有时是唯一解：用 `machine.SoftI2C(...)` 探过 I2C 总线后，GPIO14/21 会被从 I2C 外设抢成普通 GPIO，
而驱动状态跨软复位保留 → 之后**永远** `NOT FOUND`。这种情况**只能硬复位或断电重上**。
